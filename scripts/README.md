# zedge scripts

Parent: [Zedge](../README.md)

## Scope

Small operator-facing scripts that support local Zedge setup and launch behavior.

## Files

- `run-mcp-with-supervisor.sh` is the Zed context-server entrypoint: if `http://127.0.0.1:7331/health` is down, it starts `companion-supervisor.ts` in the background, waits for health, then `exec`s the MCP stdio bridge. Zed Agent uses OpenAI-compatible HTTP to that port directly (not MCP), so users who rely on Agent alone should also use `companion-launch-agent.sh` or run the supervisor manually.
- `companion-launch-agent.sh` manages the macOS launch agent for the companion sidecar (`install`, `status`, `logs`, `stop`, `kill`, `restart`, `uninstall`). **`kill`** unloads launchd and **SIGKILL**s anything still listening on **:7331** (manual supervisor too). **`restart`** runs **`kill`** then reinstalls/bootstrap from the plist if present (`pnpm run zedge:restart` at repo root). The plist runs **`node` + `gnode.js` + `companion-supervisor.ts`** with `WorkingDirectory` = monorepo root (no `pnpm` in launchd PATH) and exports `GNODE_FORCE_TSX=1` so local TypeScript source is resolved instead of stale bundled bridge code. Because Zed's OpenAI-compatible provider currently requires some provider key even for localhost, install/start seeds a non-secret `ZEDGE_API_KEY=zedge-local` launch environment value for Zed and writes `ai.forkjoin.zedge.sidecar.zed-env.plist` to restore that placeholder after OS reloads. Existing non-empty `ZEDGE_API_KEY` values are left alone, and the companion ignores the placeholder as real Edgework auth. `uninstall` removes the helper and unsets the key only when it still matches the placeholder. It tries **`launchctl bootstrap` in `gui` then `user` domain**, waits after `bootout` (avoids EIO), validates the plist with **`plutil -lint`**, falls back to **`launchctl load -w`** if bootstrap fails, and stores the working domain in `~/.edgework/zedge-launchd-domain`. Older versions used **`launchctl disable`** during stop, which could leave the next **`bootstrap`** failing with **Input/output error** — that path is removed. If an older plist used `pnpm` and never loaded, run `pnpm run zedge:launch-agent:uninstall` then `pnpm run zedge:launch-agent:install` again.
- `generate-settings.ts` fetches the live Zedge model catalog when it can, then prints a Zed provider settings snippet plus the local companion start hint. The companion snippet follows the Moonshine catalog and does not reintroduce the retired `wasm-local` picker entry.
- `run-ts-entry.sh` is the repo-local TypeScript entrypoint launcher used by the extension. It now routes the companion, supervisor, MCP bridge, and other TypeScript entrypoints through the checked-in `gnode` runtime instead of special-casing the companion shell onto Bun, and defaults `GNODE_FORCE_TSX=1` for these local entrypoints.
